# 任务、备份与缓存

## 备份与恢复

新备份增加 `pck_length`、`original_pck_sha256`、`orig_wem_sha256`、
`replacement_file` 与 `replacement_sha256`。原曲 `.bin` 和替换内容 `.bin.new`
均在清单提交及音乐包写入前持久化。C# 与 Python CLI 使用同一格式。

恢复前检查包大小、条目编号、索引位置、偏移、原容量、备份内容和原包指纹。
原包指纹通过流式读取计算，将已登记的替换区段和索引视作原始内容。
替换区段只接受原始或本次替换字节，兼容音频写入、索引写入及恢复中途退出的状态。
恢复后的音频及索引回读一致后，才删除对应记录和备份文件。

旧备份没有这些新校验值，继续执行结构、范围和长度检查后恢复，不能补证旧文件的内容完整性。
不要单独删除新格式的 `.bin.new`，它也是中断恢复核验的一部分。

## 方案执行

本地方案和市场共用 `SchemeInstallService`。先检查整批目标冲突，准备全部音频并检查容量和格式，
市场升级完成这些步骤后才恢复旧方案。每首写入前持久化安装登记；失败和取消保留成功及待恢复项。

卸载逐首更新登记，未恢复的条目及原因继续保留。备份缺失时，通过登记的原曲散列确认是否已手动恢复；
无法确认的条目保留登记。重试安装只补充剩余曲目；不完整的音乐包写入需要先恢复再安装。
登记使用临时文件、磁盘刷新和原子替换，写入错误会反馈给调用方。

## 转码、试听与进度

转码缓存位于 `build/bgm-inject-research/encode-cache`。缓存键包含源内容、编码器脚本、
采样参数、低通、循环及运行依赖的文件标识。命中前重新检查产物散列，损坏时重新编码。
重复请求共享同一缓存锁；完整产物才会原子复制到任务输出。替换任务各自使用独立输出文件名。

试听缓存以游戏包路径、文件大小、修改时间、曲目编号及原曲/当前音乐模式区分。
选择器播放原曲；曲库播放当前音乐。试听解码单独限流，不等待长时间编码任务。
窗口底部显示跨页面任务进度及取消入口。替换任务按源时长分配总进度，并为写入预留阶段。

## 验证边界

`SchemeTests` 包含合成 PCK 的异常、中断恢复、双实现互认、方案部分完成及缓存检查。
`UiTests` 覆盖真实 WPF 控件、合成静音试听、单条操作、合成包替换和取消、矮窗口固定进度栏及跨页刷新。
测试不写入真实游戏音乐包；合成音频缓存耗时对照不能代表所有整曲的编码提速。
